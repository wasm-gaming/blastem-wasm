# Video settings of BlastEm's own

## 2026-11-17 — Plan

The owner misses graphics settings specific to the engine. Today BlastEm 0.2.0 has one video
setting, `renderFilter` (Smoothing). The sibling engines have more: snes9x and mGBA give Image
filtering + Aspect ratio (+ Crop overscan / Interframe blending), jgenesis gives a blending
shader, aspect ratio and borders.

Proposed settings (all in `BLASTEM_SPEC.config`, group `video`, labels en/es):

| Key | Values | Live | How |
| --- | --- | --- | --- |
| `renderFilter` (exists) | Sharp pixels / Smooth | yes | canvas `image-rendering` |
| `aspect` | 4:3 (default) / Square pixels / Stretch | yes | the SDK's fit of the canvas in the mount |
| `overscan` | Crop (default, as BlastEm's own default) / Full border | no (on Restart) | BlastEm's `video.ntsc.overscan` / `video.pal.overscan` in the cfg the SDK writes before start |
| `scanlines` | Off (default) / On | no (on Restart) | BlastEm's `video scanlines` — **only if the wasm build renders with GL**; to check first, dropped otherwise |
| `interlace` | Double field / Single field | no | BlastEm's `video interlace` (only Sonic 2's 2P and few games), if the build honours it |

Steps:

1. Check how the wasm build renders (GL or SDL software) and how config reaches BlastEm
   (`default.cfg` baked by `scripts/build-blastem.sh`; whether `blastem.cfg` in MEMFS
   `$HOME/.config/blastem/` before `callMain` is read). Settings the build cannot honour are left
   out, and said so here.
2. `src/blastem.options.ts`: the new keys, defaults, `live`, labels and value labels.
3. `src/blastem.sdk.ts`: write the cfg overrides before start; `aspect` applied live with
   `renderFilter`.
4. The app needs no change: its Ajustes are built from the spec (the non-live ones say "Applies on
   restart").
5. README's contract section; tests for the spec (defaults, enums).
6. Release (patch → 0.3.0 by the release workflow), then play.germade bumps its pin (its record
   `2026-11-17.jgenesis-core-and-stale-engine-cache.WIP.md`).

Checks: `npm test`, build, and in Chromium the demo with a test cart: each setting changes the
picture (screenshots), and a restart keeps the non-live ones.

## 2026-11-17 13:30 UTC — Findings, what was built, checks

Adds: what the build can honour, the settings as built (they differ from the plan: all live, no
aspect, no interlace), and the checks.

**Findings**
- The wasm build renders with **WebGL** (`USE_GLES`, upstream's GL path), so shaders and scanlines
  work.
- BlastEm reads `/default.cfg` (embedded at the FS root; no `blastem.cfg` in the config dir), so
  the SDK can rewrite it before `callMain`.
- BlastEm itself scales the picture to the 640×480 canvas with `video.scaling linear` (default.cfg).
  So "Sharp pixels" (the canvas' `image-rendering: pixelated`) was never really sharp: it only
  sharpened an already smoothed picture. `renderFilter` now sets `scaling nearest` too.
- Upstream's settings menu applies video changes live with `render_config_updated()`; the overscan
  is read only in `render_init()`. So a small bridge makes everything live.
- In WebGL two upstream shaders do not compile: `crt.f.glsl` has no default float precision
  (patched in the build: `precision mediump float;` on top), `bandlimit_pixel.f.glsl` needs
  `fwidth()` (OES_standard_derivatives): left out.
- `aspect` dropped: `config_aspect()` caches its value in a function-static, so it cannot change
  live without patching upstream, and the SDK already fits the canvas at 4:3. `interlace` dropped:
  not worth a setting.

**Built**
- `scripts/web_bridge.c`: `web_set_config(path, value)` (path with `/` between levels) inserts into
  BlastEm's config tree.
- `scripts/web_render_bridge.c` (new, appended to `render_sdl.c`): `web_apply_video()` reads the
  overscan again (upstream's own loop) and calls `render_config_updated()`.
- `scripts/build-blastem.sh`: appends the render bridge, exports `_web_set_config` and
  `_web_apply_video`, patches the CRT shader's precision.
- `src/blastem.video.ts` (new): `videoEntries(config)` (settings → config entries) and
  `patchConfig(text, entries)` (sets entries in BlastEm's config text, keeping comments and
  places; adds missing keys and blocks inside their parent).
- `src/blastem.options.ts`: video settings, all live, labels en/es:
  - `renderFilter` Sharp pixels / Smooth (now also BlastEm's `scaling`);
  - `shader` "Filter": None / Sharp / CRT / NTSC composite / xBRZ;
  - `scanlines` boolean;
  - `border` Thin (BlastEm's default) / Hidden / Full.
- `src/blastem.sdk.ts`: the boot rewrites `/default.cfg` with them; a config patch with a video
  key sets each entry with `web_set_config` and calls `web_apply_video()` (skipped on an older wasm
  without it). `patchConfig` / `videoEntries` exported.
- The app is unchanged: its Ajustes read the spec.
- README: the config row and a "Video settings" section.

**Checks**
- `make test`: 19 / 19, 5 new in `tests/video-config.test.mjs` (in-place edits keep comments and
  line count, missing keys and blocks added in the parent, defaults, every shader value maps to a
  file upstream ships, upstream's real default.cfg takes every entry).
- wasm built locally with emsdk 4.0.10 (Docker has no daemon here; SDL2 2.32.0 from libsdl.org's
  tarball as a local port, as GitHub's archive is not reachable from this session). CI builds it
  with its pinned image as before.
- In Chromium, the app inside play.germade (local engine) with a test cart that draws a one-pixel
  white/red checkerboard:
  - default: crisp pixels (before: blurred);
  - Smooth: blurred, live;
  - Filter CRT, NTSC composite, xBRZ: each changes the picture, live (CRT was black before the
    precision patch);
  - Scanlines: dark lines, live;
  - Border Hidden: the top and bottom bars go, live;
  - a reload of the page keeps them (applied at boot through default.cfg).
- Not verified: a real game, a phone.

**Left**: the release (the Release workflow runs on `main` only), then play.germade bumps its pin.

Suggested commit: `feat: BlastEm's own video settings (sharp pixels, filters, scanlines, border), applied live`
