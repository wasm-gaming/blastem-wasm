# Video settings of BlastEm's own

## 2026-11-17 — Plan

The owner misses graphics settings specific to the engine. Today BlastEm 0.2.0 has one video
setting, `renderFilter` (Smoothing). The sibling engines have more: snes9x and mGBA give Image
filtering + Aspect ratio (+ Crop overscan / Interframe blending), jgenesis gives a blending
shader, aspect ratio and borders.

Proposed settings (all in `BLASTEM_SPEC.config`, group `video`, labels en/es):

| Key | Values | Live | How |
| --- | --- | --- | --- |
| `renderFilter` (exists) | Sharp pixels / Smooth | yes | canvas `image-rendering` |
| `aspect` | 4:3 (default) / Square pixels / Stretch | yes | the SDK's fit of the canvas in the mount |
| `overscan` | Crop (default, as BlastEm's own default) / Full border | no (on Restart) | BlastEm's `video.ntsc.overscan` / `video.pal.overscan` in the cfg the SDK writes before start |
| `scanlines` | Off (default) / On | no (on Restart) | BlastEm's `video scanlines` — **only if the wasm build renders with GL**; to check first, dropped otherwise |
| `interlace` | Double field / Single field | no | BlastEm's `video interlace` (only Sonic 2's 2P and few games), if the build honours it |

Steps:

1. Check how the wasm build renders (GL or SDL software) and how config reaches BlastEm
   (`default.cfg` baked by `scripts/build-blastem.sh`; whether `blastem.cfg` in MEMFS
   `$HOME/.config/blastem/` before `callMain` is read). Settings the build cannot honour are left
   out, and said so here.
2. `src/blastem.options.ts`: the new keys, defaults, `live`, labels and value labels.
3. `src/blastem.sdk.ts`: write the cfg overrides before start; `aspect` applied live with
   `renderFilter`.
4. The app needs no change: its Ajustes are built from the spec (the non-live ones say "Applies on
   restart").
5. README's contract section; tests for the spec (defaults, enums).
6. Release (patch → 0.3.0 by the release workflow), then play.germade bumps its pin (its record
   `2026-11-17.jgenesis-core-and-stale-engine-cache.WIP.md`).

Checks: `npm test`, build, and in Chromium the demo with a test cart: each setting changes the
picture (screenshots), and a restart keeps the non-live ones.
