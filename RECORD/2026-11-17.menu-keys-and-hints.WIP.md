# The keys bound to the pad's buttons work in the app's menus

## 2026-11-17 17:10 UTC — Report and plan

Report from the owner: in the pause menu's save states, on a keyboard, the keys bound to the
game's A and B (A and S) do nothing; the hints say "A" / "B" (the pad), and the menus only take
Enter / Space and Escape / Backspace. The owner wants the keys to work as the pad buttons they
are bound with, and the hints to show the key next to each pad button.

Depends on engine-specs' `setKeyAliases()` / `menuKeyAliases()` / `menuKeyHint()` (wasm-gaming/
engine-specs, record `2026-11-17.escape-in-fullscreen.WIP.md`, release 0.6.2).

Plan (`src/app/app.js`, `src/app/app.css`):
- `menuControls()`: each of BlastEm's buttons with the player's key (saved, else default) and its
  **default** pad button — the layout the SDK's pad remap shows the menus.
- `host.input.setKeyAliases?.(menuKeyAliases(menuControls()))` once settings are loaded, when a
  control is rebound or reset; `setKeyAliases?.({})` on unmount (the input is the launcher's).
- Hints: a pad button gets its key next to it (`B` `S`), lighter, from `menuKeyHint()`.
- With BlastEm's defaults: A → accept, S → back, W (Y) → more, D (C, on RB) → next. Q (X) and E
  (Z) stay the menus' prev / next, Enter (Start) stays accept.
- Bump `@wasm-gaming/engine-specs` to 0.6.2 once released (the runtime is copied next to the SDK).

## 2026-11-17 17:50 UTC — Walkthrough and checks

Adds: what was built (as planned, except the bump, which waits for engine-specs 0.6.2).

- `src/app/app.js`: `menuControls()`, `applyMenuKeys()` (after loading settings, on a rebind, on
  reset), aliases cleared on unmount; hints show the key next to a pad button when it differs
  from the button's letter (B → S; A's key is A, shown once).
- `src/app/app.css`: `.bem-hints kbd.key`, an outlined key next to the filled pad button.
- **Not mergeable before engine-specs 0.6.2**: the app imports `menuKeyAliases`, `menuKeyHint`
  and `PAD_BUTTON_NAMES` from the runtime copied next to the SDK; with 0.6.1 the module would not
  load. The dependency bump goes in this branch once 0.6.2 is on npm.
- Checks, Chromium, play.germade with this app and engine-specs' branch runtime (in the engine and
  in the launcher's input), the checkerboard cart, keyboard only:
  - pause → ↓ to slot 1 → **A** saves it ("Today · 19:47");
  - **A** on the saved slot opens its sheet ("Point 1");
  - **S** closes the sheet; **S** again goes back to the game;
  - hints: "B S continue", "B S back".
- `make test`: not affected (the app has no unit tests).

Suggested commit: `feat(app): the keys bound to the pad's buttons work in menus, and hints show them`
