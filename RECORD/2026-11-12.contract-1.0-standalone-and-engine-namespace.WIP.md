# Contract 1.0, standalone package and the engine's own storage folder

2026-11-12 · cross-repo plan: wasm-gaming.github.io `RECORD/2026-11-12.homogenize-engine-integration.WIP.md`,
play.germade `RECORD/2026-11-12.mega-drive-and-rom-library.WIP.md`. Reference engine: rsdkv4-wasm 0.3.0.

**Status:** approved by the owner ("dale a blastem"), being implemented.

## Where it is (verified at `83ff53c`, v0.1.0)

- Legacy API: `export default { manifest, load }`, `onEvent`, engine-specs `^0.1.0` as optional peer.
- `pause` / `resume` / `reset` / `destroy` are empty: "no API exposed by the Emscripten build".
- Build: upstream `tip.tar.gz` and `emscripten/emsdk:latest` — **neither pinned**, not reproducible.
- No GitHub Release has ever been published; npm has 0.1.0; Pages has a 31 MB `blastem.wasm`.
- **Saves are lost.** Upstream's web build mounts IDBFS on `/home/web_user` and writes SRAM to
  `$USERDATA/blastem/$ROMNAME`, but only from `persist_save()`, which runs at `atexit` — a page
  never exits. Also, IDBFS is one store per origin, not the engine's own folder.
- Published build does play: Old Towers v1.2 boots (Chromium, software GL).

## Changes

### A · Pinned, reproducible wasm build
- Upstream pinned by Mercurial node (`BLASTEM_REV`, today `6d1a7447ee9e`, tip of `default`, v1.0.0+22)
  and its archive SHA-256 checked; `emscripten/emsdk:4.0.10` pinned.
- Own `emscripten_pre.js` replaces upstream's: no IDBFS mount, no auto `callMain`.
- `default.cfg` patched: `save_path /save` — every save of the running game lands in one MEMFS
  folder the SDK owns.
- A small web bridge appended to `blastem.c` (`EMSCRIPTEN_KEEPALIVE`):
  `web_persist_save()` (calls `persist_save()`), `web_soft_reset()`.
- Link: `-sMODULARIZE=1 -sEXPORT_ES6=1 -sEXPORT_NAME=createBlastem`, exported runtime `FS`,
  `callMain`, exported functions `_main`, `_web_persist_save`, `_web_soft_reset`,
  `_emscripten_pause_main_loop`, `_emscripten_resume_main_loop`.

### B · SDK on contract 1.0 (like rsdkv4)
`BlastemSDK extends EngineSDKBase`, `BlastemPlay extends EnginePlayBase`, `static id = 'blastem'`.

| payload | keys |
| --- | --- |
| config | `region` (`auto`\|`us`\|`eu`\|`jp` → `-r U/E/J`), `renderFilter` (`pixelated`\|`smooth`), `jsUrl`, `wasmUrl` |
| options | none yet (BlastEm has no session-level settings worth exposing) |
| assets | `rom` — `.bin`, `.gen`, `.md`, `.smd` (bytes or a thunk) |
| storage | `namespace` (default `default`), `persist` (`'opfs'` \| `null`) |

- **Storage:** OPFS `blastem/<namespace>/` (engine-owned, same `storagePath()` as rsdkv4). Before
  boot, its files are copied into MEMFS `/save`; after `web_persist_save()` the files in `/save`
  that changed are mirrored back — every 10 s, on pause, on page hide and on `destroy()`. Emits
  `saves` when something was written.
- `pause()` / `resume()`: main loop paused/resumed and the SDL audio context suspended/resumed.
- `restart()`: soft reset. `destroy()`: final save flush, loop paused, audio closed, canvas released;
  like rsdkv4, the engine cannot be booted again in the same page (a host uses a new page/iframe).
- Self-contained ESM: contract runtime copied to `dist/blastem/engine-specs.js`, import rewritten
  (`scripts/localize-specs.mjs`, as in rsdkv4). engine-specs `^0.3.2` as a regular dependency.
- Conformance line `BLASTEM_ENGINE: EngineSDKConstructor<BlastemPayloads>`.
