# Contract 1.0, standalone package and the engine's own storage folder

2026-11-12 · cross-repo plan: wasm-gaming.github.io `RECORD/2026-11-12.homogenize-engine-integration.WIP.md`,
play.germade `RECORD/2026-11-12.mega-drive-and-rom-library.WIP.md`. Reference engine: rsdkv4-wasm 0.3.0.

**Status:** approved by the owner ("dale a blastem"), being implemented.

## Where it is (verified at `83ff53c`, v0.1.0)

- Legacy API: `export default { manifest, load }`, `onEvent`, engine-specs `^0.1.0` as optional peer.
- `pause` / `resume` / `reset` / `destroy` are empty: "no API exposed by the Emscripten build".
- Build: upstream `tip.tar.gz` and `emscripten/emsdk:latest` — **neither pinned**, not reproducible.
- No GitHub Release has ever been published; npm has 0.1.0; Pages has a 31 MB `blastem.wasm`.
- **Saves are lost.** Upstream's web build mounts IDBFS on `/home/web_user` and writes SRAM to
  `$USERDATA/blastem/$ROMNAME`, but only from `persist_save()`, which runs at `atexit` — a page
  never exits. Also, IDBFS is one store per origin, not the engine's own folder.
- Published build does play: Old Towers v1.2 boots (Chromium, software GL).

## Changes

### A · Pinned, reproducible wasm build
- Upstream pinned by Mercurial node (`BLASTEM_REV`, today `6d1a7447ee9e`, tip of `default`, v1.0.0+22)
  and its archive SHA-256 checked; `emscripten/emsdk:4.0.10` pinned.
- Own `emscripten_pre.js` replaces upstream's: no IDBFS mount, no auto `callMain`.
- `default.cfg` patched: `save_path /save` — every save of the running game lands in one MEMFS
  folder the SDK owns.
- A small web bridge appended to `blastem.c` (`EMSCRIPTEN_KEEPALIVE`):
  `web_persist_save()` (calls `persist_save()`), `web_soft_reset()`.
- Link: `-sMODULARIZE=1 -sEXPORT_ES6=1 -sEXPORT_NAME=createBlastem`, exported runtime `FS`,
  `callMain`, exported functions `_main`, `_web_persist_save`, `_web_soft_reset`,
  `_emscripten_pause_main_loop`, `_emscripten_resume_main_loop`.

### B · SDK on contract 1.0 (like rsdkv4)
`BlastemSDK extends EngineSDKBase`, `BlastemPlay extends EnginePlayBase`, `static id = 'blastem'`.

| payload | keys |
| --- | --- |
| config | `region` (`auto`\|`us`\|`eu`\|`jp` → `-r U/E/J`), `renderFilter` (`pixelated`\|`smooth`), `jsUrl`, `wasmUrl` |
| options | none yet (BlastEm has no session-level settings worth exposing) |
| assets | `rom` — `.bin`, `.gen`, `.md`, `.smd` (bytes or a thunk) |
| storage | `namespace` (default `default`), `persist` (`'opfs'` \| `null`) |

- **Storage:** OPFS `blastem/<namespace>/` (engine-owned, same `storagePath()` as rsdkv4). Before
  boot, its files are copied into MEMFS `/save`; after `web_persist_save()` the files in `/save`
  that changed are mirrored back — every 10 s, on pause, on page hide and on `destroy()`. Emits
  `saves` when something was written.
- `pause()` / `resume()`: main loop paused/resumed and the SDL audio context suspended/resumed.
- `restart()`: soft reset. `destroy()`: final save flush, loop paused, audio closed, canvas released;
  like rsdkv4, the engine cannot be booted again in the same page (a host uses a new page/iframe).
- Self-contained ESM: contract runtime copied to `dist/blastem/engine-specs.js`, import rewritten
  (`scripts/localize-specs.mjs`, as in rsdkv4). engine-specs `^0.3.2` as a regular dependency.
- Conformance line `BLASTEM_ENGINE: EngineSDKConstructor<BlastemPayloads>`.

### C · Repo
- `CLAUDE.md -> AGENTS.md`, `RECORD/` (this file).
- `src/blastem.manifest.ts`, `build-manifest`, `scripts/emit-manifest.mjs` removed (Layer A is gone
  from the contract).
- Demo: a no-build `src/demo/` page using the SDK with no import map.
- Release asset renamed to `blastem.tar.gz` with `blastem/blastem/…`, the layout the launcher fetches.
- Version **0.2.0**.

## Extension · 2026-11-13 — Plan: save states and the engine's own app (phase 3 of play.germade routes)

Owner: "ok, sigue con BlastEm" — BlastEm ships its own `EngineApp`, like rsdkv4, on engine-specs `UX.md`.

### Engine (wasm bridge)
- `web_save_state(slot)` sets `current_system->save_state = slot + 1`: upstream writes
  `/save/slot_N.state` at the next sync point (so the loop has to run for it to land).
- `web_load_state(slot)` → `current_system->load_state(current_system, slot)` (1 = found).
- Both exported in `EXPORTED_FUNCTIONS`. States live in `/save`, so the existing OPFS mirror
  (`blastem/<namespace>/`) already persists them with the SRAM.

### SDK (0.3.0, additive)
- `play.states.list()` → `[{ slot, savedAt, thumbnail }]` for slots 0-3 (mtime of
  `slot_N.state`; `slot_N.png` next to it if present).
- `play.states.save(slot, { thumbnail? })` → Promise: requests the save, runs the loop until the
  file changes if the game is paused (then re-pauses), writes the PNG, flushes to OPFS.
- `play.states.load(slot)` → boolean; `play.states.remove(slot)` (files + OPFS copy).
- `play.snapshot()` → PNG `Blob` of the current frame, captured inside an animation frame.

### App (`src/app/app.js` + `app.css` → `dist/blastem/app/`)
- Boots straight into the game (no start screen: the cartridge has its own).
- Pause (Select+Start / Escape): *Continuar*, *Guardar estado*, *Cargar estado*, *Reiniciar*
  (soft reset), *Volver* (asks first). The frame is captured as the menu opens.
- Save / load screen: four cards with the frame and date (empty slots say so); A saves or loads
  (overwriting asks first), Y deletes (asks), B back to the pause menu.
- Imports only `../blastem.sdk.js`; same look as rsdkv4's app (tokens with fallbacks).
- play.germade `engines.json` blastem → `"app": "app/app.js"`. Version 0.3.0.

## Extension · 2026-11-13 — Owner: suspend points like the Nintendo Classic Mini

Owner (linking the Super NES Classic Mini manual): "me gusta esta forma de guardar los states".
The app's states follow that model instead of a plain save/load grid:

- **Leaving creates a suspend point** — *Volver* (and leaving the page) writes the *unsaved* suspend
  point (BlastEm slot 9, with its frame) without asking: nothing is lost by leaving.
- **Opening the game shows the suspend points** when there is any: the unsaved one + four slots, each
  with its frame and date, plus *Empezar desde el principio*. A plays from the chosen one. With no
  points at all the game boots straight in.
- **Y on the unsaved point saves it** into the first free slot; with none free, pick the slot to
  overwrite (locked ones are skipped). **Y on a saved point** opens its actions: lock / unlock,
  delete (asks). Locked points cannot be overwritten or deleted (lock icon on the card).
- **Pause menu**: *Continuar*, *Puntos de suspensión* (captures the unsaved point now, opens the
  list), *Reiniciar*, *Volver al lanzador*.
- Rewind (the Classic Mini's X) is left for later: it needs a ring of in-memory states.

SDK shape adjusted: slots 0-3 are the player's, `AUTO_STATE_SLOT = 9` is the unsaved point;
`states.list()` → 0-3, `states.get(slot)` any; `states.copy(from, to)` (state + frame);
`states.lock(slot, locked)` (a `slot_N.lock` marker in the save folder, mirrored like the rest);
`save`/`remove` refuse a locked slot.

## Extension · 2026-11-13 — Walkthrough: save states + suspend-point app (implemented, 0.3.0)

- `scripts/web_bridge.c`: `web_save_state(slot)` (sets `save_state`, slots 0-9) and
  `web_load_state(slot)`; exported in `build-blastem.sh`. wasm rebuilt in emsdk 4.0.10 (Docker,
  `BUILD_CA_BUNDLE` + `BUILD_SDL2_SRC`).
- SDK: `STATE_SLOTS = 4`, `AUTO_STATE_SLOT = 9`, `play.states` (`list`, `get`, `save`, `load`,
  `copy`, `lock`, `remove`), `play.snapshot()`. States, frames (`slot_N.png`) and locks
  (`slot_N.lock`) live in `/save` and ride the existing OPFS mirror; removals also delete the OPFS
  copy. **Found:** BlastEm paces itself on the SDL audio callback, so a paused game never reached a
  sync point (the save request waited forever). Saving while paused now runs the loop with the
  audio resumed through a zero gain, then freezes again (~17 ms).
- `src/app/app.js` + `app.css` (Makefile `build-app` in `build-sdk`, `exports["./app"]`): boot →
  suspend-point list when there is any (else straight into the game); unsaved point + slots 1-4 +
  "Desde el principio"; Y saves the unsaved point to the first free slot (or pick one to overwrite,
  locked ones skipped); Y on a saved point → Bloquear / Desbloquear, Borrar (asks; disabled when
  locked); pause: Continuar, Puntos de suspensión, Reiniciar, Volver al lanzador (writes the unsaved
  point, no question). Frame captured inside an animation frame as the pause menu opens.
- Verified in Chromium via play.germade `/megadrive/?game=final-fight-md-plus…`: pause → points
  (unsaved point with frame) → V saves into slot 1 → lock → back to pause → Volver (left to the
  library) → reopening shows the points (unsaved + locked slot 1) → slot 1 loads into the game.
  Direct SDK test: save running, save paused, list. `make test` 14/14.
- Not yet: rewind (Classic Mini X), real-gamepad check.
